# 引擎与 UI/UE 实践指南

本文记录《星命水浒》当前 Canvas/Phaser 页面引擎与战斗引擎的推荐实现方式。目标是让界面首先像一个可玩的游戏，再像一个信息完整的工具。

## 1. 引擎架构

- **模型驱动渲染**：页面状态先由 `src/engine/models/*` 转成纯数据模型，再由 `GameStage` 绘制。页面逻辑不直接操作 Phaser 对象。
- **语义层与绘制层分离**：Canvas 负责构图、氛围和低延迟反馈；DOM 只保留屏幕阅读器语义、原生滑杆、文件选择等更适合原生控件的输入。
- **单一持久场景**：页面切换只替换模型，不重建 Phaser 场景。只有进入战斗时才创建独立战斗画布，避免 WebGL 上下文来回销毁。
- **资源预加载**：所有页面图片先通过 Phaser Loader 入纹理缓存，绘制时只使用纹理键。异步加载完成后主动重绘一次。
- **渲染时机**：模型变更、视口变化、资源加载完成才重绘；不要每帧重建整个页面 UI。
- **层序固定**：背景图、暗部遮罩、场景图形、交互 UI、弹窗。弹窗遮罩必须切断底层命中区。

## 2. 页面构图

不同玩法页不能共用同一套“顶部横幅 + 操作条 + 卡片列表”。推荐保持以下差异：

- **标题页**：电影主视觉。标题、副标题和菜单直接压在场景暗部上，不放大圆角面板。
- **江湖地图**：左边是当前回目标与行军决断，右边是可辨认的章节路线图。当前回必须有明确红色标记。
- **好汉名册**：角色选择式构图。左侧展示当前好汉和操作，右侧用大立绘卡阵浏览其他好汉。
- **梁山营寨**：经营视图。顶部放资源与整备动作，下方用建筑地块表达建造、产出和未解锁状态。
- **战斗**：战场优先。HUD 使用窄侧栏或底部托盘，技能是可扫视的招式盘，不能做成纵向设置表。
- **剧情与奖励**：剧情保持对话焦点；奖励页先展示战果，再展示收集与长线信息。

## 3. 视觉规则

- 主背景至少保留 40% 无遮挡区域，避免每页都被半透明黑块覆盖。
- 页面只允许一个主行动使用高饱和强调色；次行动使用铜色，其他操作使用低对比描边。
- 面板透明度以 0.72–0.9 为常用区间；正文背后的背景必须仍可感知，但不能影响阅读。
- 角色立绘和场景图承担叙事，图标只承担识别。不要用同一枚通用建筑图标解释所有设施。
- 标题使用宋体或具有笔锋的展示字体；正文使用系统无衬线字体。禁止负字距。
- 图像上压字仅用于章节卡和角色卡，必须叠加局部暗部并标记为装饰性图片，避免布局审计误报。
- 数字、状态和资源需要稳定的独立区域，避免动态长度改变按钮或卡牌尺寸。

## 4. UI/UE 交互

- 触控命中区域不小于 `44 x 44`；小屏卡片最低高度保持 `50–56`，主要按钮保持 `44`。
- 所有操作必须有可见悬停/按下反馈，并在 `180–260ms` 内完成页面切换或明确 loading 状态。
- 导航位置固定：桌面左侧，移动端底部。页面内主行动不得和导航争夺同一区域。
- 列表容量不足时使用分页或“更多”入口，禁止让末行卡片滑到导航栏后面。
- 危险操作、不可用操作和锁定状态必须同时通过颜色、图标、文案区分，不能只靠颜色。
- 战斗保留“选择招式 → 选择目标”的两步结构；取消、合击、自动战斗、速度和暂停都应是独立命中区。
- 动画尊重 `prefers-reduced-motion` 和游戏内“减少动态效果”设置。

## 5. 响应式与安全区

- 基准验证视口：`1440x900`、`1280x720`、`800x600`、`390x844`、`320x568`。
- 移动端优先保证标题、当前目标、主行动、导航四类信息；低优先级说明可以压缩为一行。
- 底部导航和原生表单必须使用 safe-area inset。
- 任何文字不得越出父容器，不得覆盖后续内容，不得与图标发生非预期重叠。
- 固定格式元素使用明确宽高或比例约束，禁止因奖励数字、冷却文字或本地化长度改变整体布局。

## 6. 战斗与性能

- 战场角色位置、HUD、飘字和 VFX 分层管理；角色 HUD 只在其文本或数值变化时更新。
- 高频特效使用对象池或短生命周期精灵，并确保在 tween 完成、停止和场景销毁时释放。
- 大型角色图和背景图使用 WebP、纹理复用和合理尺寸；不要每场战斗重新解码。
- 字体应在首帧前通过 `FontFace` 加载，正式版本内置有授权的 CJK 字体子集。
- `battle-stage.js` 后续应拆为布局、HUD、技能盘、VFX、输入五个模块，降低单文件复杂度。
- 画布尺寸变化必须同时更新 Phaser scale、角色布局、命中区和 DOM 代理层。

## 7. 无障碍

- Canvas 页面同步生成隐藏语义树：页面标题、摘要、导航、当前操作、标签页、卡片、弹窗。
- 使用 `aria-current`、`aria-pressed`、`disabled` 表达状态，不依赖视觉类名。
- 键盘和标准手柄都要能完成完整流程；焦点在页面切换后恢复到合理位置。
- 原生滑杆、文件导入和质量选择使用 DOM 控件，避免在 Canvas 内重复实现复杂输入。
- 错误、成功和战斗结果通过 `aria-live` 区域播报。

## 8. 验证门禁

每次 UI 改动至少执行：

```bash
npm run check:js
npm test
npm run test:battle-layout
npm run test:battle-vfx
npm run test:engine-pages
npm run test:e2e
```

页面引擎测试必须检查：文字碰撞、图标文字碰撞、命中区重叠、越界、滚动容器、图片加载和五档视口。视觉截图只用于人工判断，不能替代结构审计。

## 9. 当前优先级

1. 继续拆分 `battle-stage.js`，并把角色 HUD 改为脏状态更新。
2. 为战斗技能、目标准则、取消、合击和菜单补齐键盘/手柄完整路径。
3. 内置正式 CJK 字体并确保首帧前加载。
4. 为营寨、异闻、星图和奖励页继续做各自独立的玩法构图，避免重新退回通用后台样式。
5. 在真实 Windows、macOS、Steam Deck、手柄和触屏硬件上完成最终体验验收。
